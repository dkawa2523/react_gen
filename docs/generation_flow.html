reactgen / discover / acquire

入力ガスから反応式・状態リストまで

ガス名を受け取ってから反応式リストと状態リストを書き出すまでに、どの処理がどのデータを使って 何を判定しているか。判定点はインディゴ、データ源はティール、 棄却は赤で示します。

00目的

ガス名を入力し、妥当かつ網羅的な化学種リストと反応式リストを出力する。 多段(生成物のさらなる反応まで)で、イオンと励起状態を含みます。存在量と速度係数は 意図的に後回しで、この出力が DNT+ の計算対象を決めます。 

rgen generate  cases/ar_o2/case.yaml       # レジストリのみ。候補生成なし
discover network --gas Ar --gas CF4        # レジストリ + 候補生成
acquire asd Ar O F  →  rgen ingest  →  --overlay work/levels   # 外部データの取り込み

01データ源

レジストリはファイル群、オーバーレイはメモリ上でマージされます。curated なファイルは書き換えません。

場所持っているもの
registry/species/ 組成・電荷・state(kind / label / energy_eV / resolution / members)・properties・NASA多項式
registry/reactions/ 族ごとのチャンネル(type, threshold_eV, datasets, status)と、ペアの potential
registry/materials/表面材料と付着係数
registry/datasets/断面積表、速度係数
overlay(任意)rgen ingest が受理したもの。熱化学、原子準位など

射影 — 候補生成がレジストリを引く見方

view返すもの出どころ
known()(組成, 電荷) → 種ID全種。基底状態を優先
ionization()種 → IE [eV]プロパティ、無ければ電離反応の閾値。励起状態は IE(X)−E で導出
affinity()種 → EA [eV]electron_affinity_eV
enthalpy()種 → ΔHf [eV]プロパティ。励起状態は Hf(X)+E で導出
excitation()種 → {metastable / resonant / lumped: eV}NIST ASD 由来
基底状態の優先が要ります。 O と O_1D は組成も電荷も同じです。 索引が後勝ちだと断片の命名が励起状態を拾い、e + SO → e + O_1D + S を生成します。

励起状態の値は導出です。 Hf(X*) = Hf(X) + E、IE(X*) = IE(X) − E。推定ではなく恒等式で、 導出した IE(Ar_4s) = 4.16 eV はレジストリの独立した実測閾値と一致します。

監査は式の構造だけを見るので数値が要らず、どのレジストリでも常に走ります。 品質はデータの有無と整合を見ます。

品質(quality)— データは揃っているか

役割ごとに要求する物性が決まっており、役割は種が網にいることから決まります(反応式からではありません)。

役割要求する物性

太字が篩用です。これを要求しないと「この種の ΔHf が無いのでこのペアが篩えない」が無言になり、 何を取れば何が動くかが分かりません。ほかに conflicting_rate_form / competing_datasets / out_of_range / missing_cross_section / missing_sticking_coefficient / undeclared_reverse / out_of_scope があります。

05判定レイヤー

何を根拠にその反応がリストにあるのかを、4つの別々の問いとして記録します。 1つの「信頼度」にまとめると、熱化学的に確実だが誰も述べていない反応と、 出典はあるが速度が未測定の反応が区別できなくなります。

レイヤー問い答えの種類
structureこの種は存在しうるか、式は保存するか conserved / conserved, species proposed
thermochemistryエネルギー的に開いているか exothermic by N eV / endothermic by N eV / unknown
kineticsこの条件で効くほど速いか fast / comparable / slow / negligible / unknown
attestation出典がこの反応を述べているか 出典名 / unattested
not_run と unknown は別の答えです。 前者は「そのレイヤーを評価していない」、後者は「評価したが判定できない」。 --layers structure,thermochemistry のように選ぶと、残りは not_run になります。

レイヤーごとの判定基準と式

structure

① 未登録の種が式に含まれる                      → 棄却
② |Σq(反応物) − Σq(生成物)| > 1e-9              → 棄却  ※表面反応は免除
③ 各元素で Σ n·count が一致しない                → 棄却
④ 配位子数 > Σvalence(骨格) − 2(骨格数 − 1)      → 棄却  ※重粒子衝突のみ
⑤ 3個以上の配位子は原子として離脱(F3 を防ぐ)

①〜③は 例外なく全反応に適用され、破れば rejected_reaction(blocking)。 質量は別途見ません — 元素が合えば質量は合うためです。 ④は現在 collide.py にのみあり、電子衝突には適用されていません。

thermochemistry

ΔH = Σ Hf(生成物) − Σ Hf(反応物)
     Hf(A⁺) = Hf(A) + IE(A)        Hf(A⁻) = Hf(A) − EA(A)

両辺に同数ある骨格は値を引かずに相殺する
  → 電荷交換は ΔH = IE(B) − IE(A) となり、Hf が無くても解ける
反応型篩の基準由来
charge_transfer
dissociative_charge_transfer
reactive_scattering		 ΔH ≤ 2.0 eV(--max-endothermic) 400 K の kT は 0.034 eV。バルクでは 2 eV 上は走らず、届くのはプレシースで加速されたイオン
penning_ionizationΔE = IE(X) − E_exc < −0.25 eV 数 kT。見えない活性化障壁の代わり
dissociation(励起断片)篩なし。ΔE = D0 + E(準位) を記録 熱力学的下限。実測閾値はこれ以上(O2 で計算 7.13 / 実測 8.57)

07DNT+ への引き渡し

イオン衝突の断面積は外部データベースにありません。だから DNT+ が計算します。 本コードの役割は何を計算すべきかを決めることです。

ペアは反応式ではなく種から列挙します。 反応式が既にあるペアだけを渡すと、データが無いペア — つまり計算が必要なまさにそれ — が 指示書から漏れます。イオンと中性が出会えば、化学変化の有無に関わらず弾性散乱と捕獲は起きます。
索引の項目意味
pairs_total網内のイオン × 中性。計算対象の全体
no_known_channel反応式が1本も無いペア。DNT+ が存在する理由
resonant対称電荷交換。組成が同じなら構造的に判定。断面積が最大の過程
summary.long_range分極率・双極子・質量が揃い、今すぐ走れるペア
summary.full短距離ポテンシャルも揃い、非弾性・反応チャンネルまで出せるペア
blocked_byそのペアに何が足りないか

入力文書は実行可能なペアにだけ書きます。数千の空スタブを書くと走らせられるものが埋もれるためです。 なお短距離ポテンシャルの取得は DNT+ 側の仕事で、本コードは blocked_by で 足りないことを言うところまでです。

08いま埋まっていないもの

リストの内容として欠けているものはありません。残りはすべて数値です。

  • 振動量子 — V-T の ΔH と振動励起の閾値。振動定数があれば埋まります。
  • 分子の電子励起閾値 — LXCat の手動エクスポート。原子は NIST ASD から自動取得できます。
  • 硫黄フッ化物5種の ΔHf(SF, SF3, SOF, SOF3, SOF4)— 燃焼化学に現れないため既存編纂物に存在しません。
  • 短距離ポテンシャル — DNT+ の入力。本コードの範囲外です。

いずれも gaps.yaml が種と反応を名指しした上で何が足りないかを書いており、 リスト自体は成立しています。

reactgen はネットワークに触れません。取得は acquire、 候補生成は discover の責務で、import-linter が契約として検査しています。
