# ラジカルの分極率をどこから取るか

`CF, CF2, CF3, SF, SF2, SF3, SF4, SF5, SO, SOF, SOF3, SOF4, SO2F2, FO` —
放電を構成するラジカル群の分極率を、どのデータベースから、どの方法で取れるか。

**結論を先に: 実測値を持つデータベースは存在しません。** 以下はすべて実測した結果です。

---

## 1. 当たった経路と結果

| 経路 | 結果 | ラジカル |
|---|---|---|
| `chemicals` / `thermo` | **分極率の表そのものが無い** | — |
| `mendeleev` | **原子は正確**(Ar 1.642 対 実測 1.641) | 原子のみ |
| cantera `transport.polarizability` | 9 / 102 種 | ✗ |
| `chemicals` 屈折率 → Lorentz–Lorenz | 3 / 57 種 | ✗ |
| **CCCBDB 実験値一覧**(`pollistx.asp`) | **261種、自動取得可**(実装済み) | **✗ 一つも無い** |
| CCCBDB 計算値(`polcalc2x.asp`) | PM6 と Miller ahc のみ | △ 下記 |
| QCArchive REST API | 到達するがベンチマーク単位の構成 | ✗ |
| Alexandria library (Zenodo) | HTTP 403 | — |

### 1.1 `chemicals` を徹底確認した結果

分極率に関わるものは `polarizability_from_RI(RI, Vm)` **一つだけ**で、
分極率の列を持つデータファイルは `chemicals`・`thermo` の全同梱データ中**ゼロ**でした。

お心当たりは `acquire molecular` の方だと思われます。これは `chemicals` から
**双極子モーメントと Lennard-Jones 径**を取っており、分極率は取っていません。

### 1.2 CCCBDB の計算値は使えない

フォーム(`getformx.asp` への POST)で種ごとに引けることは確認しました。
既知の実測値がある種で精度を測ると:

| 種 | 実測 | PM6 | Miller ahc | MP2/6-31G* |
|---|---:|---|---|---|
| CF4 | 2.824 | 2.196(−22%) | 3.041(+8%) | — |
| SO2 | 3.882 | 3.622(−7%) | — | — |
| F2 | 1.160 | 1.322(+14%) | 1.054(−9%) | — |
| CO2 | 2.507 | 1.998(−20%) | 2.660(+6%) | — |
| NH3 | 2.103 | — | 2.138(+2%) | 1.623(−23%) |
| **SF6** | 4.490 | **何も無し** | — | — |

そして肝心のラジカルでは:

```
CF3:  PM6 = 1.783    Miller ahc = 1.294
CF4:  PM6 = 2.196    Miller ahc = 3.041
```

**ahc の CF3/CF4 = 0.43** です。F を1つ外して分極率が57%落ちる分子はありません。
Miller の ahc は混成状態を入力に取るため、ラジカル炭素で破綻していると見られます。
PM6 は半経験法で、閉殻種ですら −22% ずれます。

## 2. 加成則の当てはめ — 実際にやってみた

CCCBDB の実験値のうち、本レジストリが使う18元素だけで構成される **243種**を訓練データとし、

$$\alpha = c_0 + \sum_i n_i c_i$$

を最小二乗で当てはめました。Leave-one-out:

| 形 | LOO 中央値 | 90パーセンタイル | 最大 |
|---|---:|---:|---:|
| 電子数のみ | 20.9% | 87% | 294% |
| 元素加成(切片なし) | 4.5% | 19% | 100% |
| **元素加成(切片あり)** | **4.4%** | **18%** | 106% |
| 元素加成 + 電子数 | 4.4% | 18% | 245% |

得られた寄与(Å³/原子): `C +1.377  F +0.222  O +0.545  S +2.769  H +0.249  Si +3.699  切片 +0.429`

**アンカーに対する成績**(訓練から抜いて予測):

| 種 | 実測 | 予測 | 誤差 |
|---|---:|---:|---:|
| SF6 | 4.490 | 4.535 | **+1.0%** |
| CF4 | 2.824 | 2.687 | −4.8% |
| SOF2 | 3.927 | 4.203 | +7.0% |
| C2F6 | 4.668 | 4.497 | −3.7% |
| PF3 | 4.414 | 4.375 | −0.9% |
| NF3 | 2.810 | 1.917 | **−31.8%** |
| F2 | 1.160 | 0.866 | −25.4% |
| SiF4 | 3.319 | 5.314 | **+60.1%** |

文献の Bosque–Sales 係数(有機液体に当てはめたもの)を直接使うと SF6 で +36%、
F原子で +39% だったので、自前で当てはめる方が明確に良いです。

**ラジカルへの予測値**(単調で物理的な並びにはなっています):

```
CF  2.03   CF2 2.25   CF3 2.47   CF4 2.69 (実測 2.82)
SF  3.42   SF2 3.64   SF3 3.86   SF4 4.09   SF5 4.31   SF6 4.53 (実測 4.49)
SO  3.74   SOF 3.96   SOF3 4.41   SOF4 4.63   SO2F2 4.73   FO 1.20
```

## 3. なぜ既定パイプラインに入れないか

`acquire additivity` として実装しましたが、**`tools/refresh_properties.py` には入れず、
`rgen adopt` の対象にもしていません。** 理由は kinetics レイヤーの契約です。

kinetics レイヤーの主張は「**この反応はこれより速くならない**」という片側上限です。
ところが:

- 訓練データは **すべて閉殻分子**
- ラジカルは不対電子を持ち、同じ組成の閉殻種**より分極しやすい**
- したがってこの予測値は**系統的に低い**
- Langevin は $k_L \propto \sqrt{\alpha}$ なので、低い $\alpha$ は低い $k$ を与える
- **超えられる上限は上限ではありません**

レジストリに入れると、保証が黙って推定に変わります。

代わりに、**順位づけには使えます。** 1180 ペアのうちどれを先に計算すべきかという問いは
推定値で答えられる問いで、それがまさに DNT+ に投げる問いです。

```powershell
# 明示的に呼ぶ。overlay として使い、adopt はしない
acquire additivity cases/ar_sf6_o2/candidates/species.yaml --out work/estimated
rgen generate cases/ar_sf6_o2/case.yaml --overlay work/estimated/snapshot.yaml
```

出力される値には `quality: estimated` が付き、出典欄に LOO 誤差と
「閉殻で訓練したのでラジカルは低い」という但し書きが入ります。

## 4. 実測値を得るには

残る手段は2つだけです。

**(a) 文献の個別値。** CF3・CF2 などは分光・散乱実験や高精度計算の論文が個別に存在します。
20種程度なので手入力は現実的です。取り込み口(`rgen ingest`)は既にあります。

**(b) 量子化学計算。** 分極率は有限場法か応答理論で求められます。基底関数に
**拡散関数が必須**(aug-cc-pVDZ 以上)で、これを欠くと 20〜30% 低く出ます
— 上の CCCBDB MP2/6-31G* が NH3 で −23% だったのがその例です。
1分子あたり数分〜数十分程度で、対象20種なら現実的な規模です。

以前「量子科学計算はまだ検討しない」との判断でしたので (b) は保留していますが、
**ラジカルの分極率に関しては、これが唯一の実測相当の手段**であることが今回の調査で確定しました。
必要になった時点で、対象を20種に絞った形で再検討する価値があります。
