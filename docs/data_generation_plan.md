# DBで得られない量を作成するための将来設計

2026-10-13。これは未実装の検討項目です。現在の取得・判定処理へ計算ソルバーを
追加した仕様ではありません。空のpackage、仮CLI、仮interfaceは作成しません。
必要な対象・量・用途と検証方法が決まった計算法から実装します。

## 配置と依存方向

将来、プロジェクト内の `data_methods/` に、計算法ごとの独立packageを置きます。
以下は責務の例で、package数や実装技術を固定するものではありません。

```text
data_methods/                       # 将来作成する別ディレクトリー
  quantum_thermochemistry/           # 独立pyproject・src・tests・README
  thermal_kinetics/                  # 独立pyproject・src・tests・README
  electron_collisions/               # 独立pyproject・src・tests・README
```

各packageは独立した依存関係・対応Python・検証・配布版・明示CLIを持ちます。
必要な量子化学ソフトや衝突・master equationソルバー、実行環境、ライセンスを
そのpackageで管理し、`plasma-reactgen` の通常インストールへ要求しません。
本体はこれらをimport、自動起動、実行環境の構築、外部サービスへの送信をしません。
利用者が計算を明示実行し、作成されたファイルを本体へ渡します。

```text
不足対象と必要量の確認
  -> 独立packageへの明示入力・計算
  -> 共通snapshot + 原入力・原結果・数値asset
  -> 本体の共通読込み、必要に応じingest
  -> 量・対象・条件の審査と分析入力での選択
  -> 必要に応じ明示adopt
```

既存ソフトの原形式を渡す場合は `acquire` の対応converterを使います。
独立packageが既存の共通snapshotを出力した場合は直接読み込めます。
同じ対象・量の評価はDB取得記録と共通で、計算法名による別判定は作りません。
本体内部の可変型への直接依存を避け、文書化されたsnapshotとasset形式を境界にします。
共通形式で表せない物理量・参照条件が必要になった場合は、その実際の利用処理と
一緒に共通形式を拡張します。未知の条件を保存しただけでは評価対応にしません。

## 各方法の必要入力と保証範囲

必要項目は選んだ計算法と出力量から決めます。すべてのpackageに同じ入力一式を
要求したり、ガス名だけで構造・電荷・スピン・参照状態を補ったりしません。

| packageの責務例 | 方法に応じた必要入力 | 出力する量 | その結果だけでは決まらないこと |
|---|---|---|---|
| `quantum_thermochemistry` | 相・構造・電荷・電子状態、計算法・基底、必要な振動/零点/熱補正、生成量の基準と参照反応、出力温度域 | 定義付きIE/EA、参照条件付き形成量、Cp/H/Sや対応する熱化学表現 | 電子全エネルギーだけでは生成エンタルピーにならない。反応速度、生成物分岐、現象成立を保証しない |
| `thermal_kinetics` | 反応と状態、必要なポテンシャル・遷移状態・周波数等、選択した近似。圧力依存には浴ガス・エネルギー移行と温度/圧力域 | TSTの速度係数、RRKM/master equation等による適用条件付きk(T,p) | ΔH/ΔGだけでは速度は決まらない。熱的モデルを非平衡分布や別浴ガスへ無条件に転用できない |
| `electron_collisions` | 標的の構造・電子状態、衝突量の定義、エネルギー域、選択法の電子構造・軌道等の入力 | 定義と総量/部分量を持つエネルギー依存断面積 | 総電離から生成物別分岐、付着、励起は決まらない。断面積の計算だけでは分布積分済み速度係数にならない |

量子化学から生成量を作るには、共通理論レベルでの参照反応と必要な零点・温度補正が
必要です。単独の電子エネルギーの単位換算を生成量としません。
[NIST CCCBDBの公式説明](https://cccbdb.nist.gov/enthformationx.asp)

熱速度の計算は熱化学とは別の工程です。たとえばArkaneは量子化学結果からの
統計熱力学、遷移状態理論、圧力依存master equationを区別しています。
使用する補正や縮約法も計算記録へ残します。
[Arkaneの公式説明](https://reactionmechanismgenerator.github.io/RMG-Py/users/arkane/introduction.html)

BEBを選ぶ場合は軌道の束縛エネルギー・運動エネルギー・占有数等を必要とし、
モデルが近似する総電離量を出力します。NISTの説明では最小束縛エネルギーに
垂直IEを推薦しています。これは基底状態間の熱力学判定が使う断熱IEとは別用途です。
必要な近似値を既存の断熱IE欄から無言で代用しません。
[NIST BEBの公式説明](https://pml.nist.gov/PhysRefData/Ionization/intro.html)

R-matrix等の別衝突計算法や表面反応モデルが必要になった場合も、実際の入力と
出力量・適用域が説明できる単位で追加します。材料・表面状態・被覆・入射条件を
必要とする量を、ガス種だけの万能物性として登録しません。
測定による補完は実験条件・校正・原結果を持つ外部/ローカル記録の入力経路として扱い、
計算solver packageへ押し込めません。

## 保存、資格、再現性

出力は既存の表記辞書・共通snapshotへ合わせ、少なくとも対象と量の定義、単位、
その量に必要な参照条件・適用域、原入力・原結果・数値assetとhash、ソフトと版、
計算法・近似、出典を保持します。収束・打切り・乱数を使った計算には、その範囲と
再現条件を残します。未評価の不確かさは不明として保存し、零誤差を宣言しません。

理論計算は `method: calculated`、推定は `estimated` として区別します。
計算成功・正常終了・収束は、その量の科学的レビューや実験的な精度保証ではありません。
既定では未審査の資格を保持し、採用可能性は対象・量・条件と必要なレビューで判断します。
出力形式の受理から `state_existence` や `channel_assertion` を自動で承認しません。
他DBからの同じ量と同列の独立記録として保存し、原出典や既存記録を上書きしません。

各packageは次元、既知の極限、参照条件、少数の出典付き回帰例、snapshotの往復を
検証します。失敗した計算、形式エラー、不足入力は明示し、空の値を成功結果へ変えません。
本体は対応する物理量だけを消費し、未対応モデルが必要ならその作業を別途返します。

## 難しいデータの引継ぎ

現在の不足一覧から、対象・量・利用したい結論・必要な条件域を引き継ぎます。
取得できない原数値、原条件や対象の未確認、未測定量、実装未対応モデルを区別し、
「公開検索で見つからない」を現象や量の不存在へ読み替えません。

既存記録を検索・取得しても不足が解消しない対象は、原資料の追加確認、理論計算、
測定の候補として残します。まず方法が目的量を実際に出せるかと必要入力を確認し、
計算・測定の選択を明示します。断面積からの係数変換のような未対応モデルは、
追加測定が必要な欠測と分けます。packageを作っただけで保留対象を解消扱いにしません。

最初の実装は、具体的な不足対象と根拠付き検証例が揃った一つの方法に限定します。
本書は将来の接続方針で、現在の通常利用に新しい入力・依存・手順を要求しません。
